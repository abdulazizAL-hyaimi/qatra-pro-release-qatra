# قطرة برو 2.5 — مرشّح التوزيع التشغيلي

المشروع يحافظ على واجهات HTML/CSS/JavaScript والطباعة الحرارية والتقارير الموجودة، ويضع تحتها طبقة Android أصلية جديدة للتخزين والمزامنة.

## ما نُفّذ

- مشروع Gradle واحد ينتج أربع حزم مستقلة: `admin` و`reader` و`collector` و`cashier`.
- قفل دخول أصلي مستقل لكل تطبيق؛ لا يدخل الرمز إلى JavaScript، وتُحفظ بصمته بواسطة مفتاح HMAC غير قابل للاستخراج من Android Keystore.
- دخول اختياري بالبصمة عبر نافذة Android النظامية، مع بقاء اسم المستخدم وPIN كخيار احتياطي وعدم حفظ PIN لأجل البصمة.
- هوية بصرية موحدة للإدارة والكاشف والمحصل والصندوق وصفحات إدارة الأدوار، مع تنقل سفلي للهاتف وتخطيط متجاوب للأجهزة اللوحية.
- SQLite هو المصدر الدائم للبيانات، مع جداول للحالة، فهرس السجلات، عمليات المزامنة، التأكيدات، الترحيل، والتدقيق.
- JavaScript Bridge بصلاحيات محددة لكل حزمة، ولا يسمح لأي دور بفتح نطاق بيانات دور آخر.
- ترحيل `localStorage` مرة واحدة عند توفره، وترحيل يدوي لنسخ JSON القديمة.
- تشفير AES-256-GCM موثّق لملفات المزامنة، ونسخ احتياطية محمولة محمية برمز استعادة مستقل عن الجهاز.
- مفتاح المزامنة المشترك يُنقل داخل ملف ربط محمي بـPBKDF2، ثم يُلف ويُحفظ محليًا بواسطة Android Keystore؛ المفتاح لا يصل إلى JavaScript.
- منع تكرار العملية بواسطة `packageId` و`operationId` وقيد فريد داخل SQLite.
- حفظ الحالة وتسجيل العملية المستوردة في معاملة SQLite واحدة لمقاومة الانقطاع.
- ملف تأكيد مشفر بعد كل استيراد، ويمكن للمرسل اعتماده لتغيير حالة العملية الصادرة إلى `ACKNOWLEDGED`.
- حذف مفتاح التوقيع القديم وكلمات مروره وملفات JSON/CSV المضمنة وبيانات المشتركين من المصدر.
- منع النسخ الاحتياطي السحابي لقاعدة البيانات والمفاتيح، ومنع cleartext وفتح صفحات ويب خارجية داخل WebView.
- إيقاف الإدخال تلقائيًا إذا تعطلت SQLite أو JavaScript Bridge بدل العمل بذاكرة مؤقتة قد تفقد البيانات.
- عدم اعتبار القراءات أو السندات مسلّمة إلا بعد نجاح كتابة ملف المزامنة على الجهاز.
- «بدء التشغيل الفعلي» إجراء لمرة واحدة؛ بعده يُمنع مسح التشغيل وترحيل JSON غير المشفر.
- محاسبة عامة بالقيد المزدوج مشتقة من الفواتير والتحصيلات والمصروفات والصندوق دون إنشاء قيود تشغيلية مكررة.
- دليل حسابات قابل للتوسعة، ودفتر يومية، وأستاذ عام، وميزان مراجعة، وقائمة دخل، ومركز مالي، وتدفقات نقدية، وأعمار ديون.
- فصل الصندوق والبنك وعهد كل محصل والدفعات المقدمة وذمم المشتركين والموردين ومراكز التكلفة.
- قيود يدوية متوازنة فقط، وتصحيح بقيد عكسي موثق، وتسوية بنك/صندوق، وإقفال شهري يمنع الإدخال والاستيراد في الفترة المقفلة.

## ترحيل النسخة القديمة

مفتاح التوقيع الجديد لا يستطيع تحديث تطبيق موقّع بالمفتاح القديم. لذلك:

1. من كل نسخة قديمة، صدّر نسخة JSON قبل إزالة التطبيق القديم.
2. احتفظ بالملفات خارج الهاتف وتحقق من فتحها.
3. أزل التطبيق القديم وثبّت APK الجديد الموافق للدور.
4. في الإدارة اختر «استيراد نسخة/ترحيل JSON قديم». في المحصل والصندوق استخدم «استعادة نسخة احتياطية» واختر ملف JSON القديم.
5. بعد نجاح الترحيل، أنشئ نسخة محمولة برمز استعادة واحذف النسخة النصية بعد التأكد من النسخة الجديدة.

## النسخ الاحتياطية بعد حذف التطبيق

- النسخ الجديدة تستخدم الصيغة `QATRA_PORTABLE_BACKUP_V2`، ولا تعتمد على مفتاح Android Keystore الذي يُحذف عند إزالة التطبيق.
- عند التصدير تظهر نافذة Android لاختيار رمز استعادة من 8 إلى 64 محرفًا وتأكيده. الرمز لا يصل إلى JavaScript ولا يُحفظ داخل التطبيق.
- خزّن ملف النسخة ورمز الاستعادة في مكانين منفصلين. فقدان الرمز يجعل فك النسخة غير ممكن.
- بعد إعادة التثبيت، اختر ملف النسخة أو اضغط عليه من مدير الملفات، ثم أدخل رمز الاستعادة واضغط «حفظ الاستيراد».
- نسخة الإدارة المحمولة تشمل بيانات التشغيل وسجل المستخدمين وتكليفات الكاشف والمحصل وإعدادات الصندوق، وتُعاد جميع نطاقاتها في معاملة SQLite واحدة.
- إذا كان التطبيق مرتبطًا بشبكة مزامنة، يُضمّن مفتاح الشبكة داخل النسخة بعد لفّه برمز الاستعادة؛ يُستعاد داخل Android Keystore ولا يظهر في JavaScript.
- النسخ القديمة الصادرة قبل هذا الإصلاح ما تزال مرتبطة بمفتاح المزامنة القديم. لاستعادتها يجب أولًا استيراد ملف `.qpair` الأصلي ورمزه من شاشة «الأمان». بدون مفتاح الربط الأصلي لا يمكن فك النسخة القديمة تشفيريًا.

## ربط مفاتيح المزامنة

1. افتح زر «الأمان» في الإدارة.
2. أدخل رمزًا قويًا من 8 إلى 64 محرفًا وأنشئ ملف `.qpair`.
3. انقل الملف إلى أجهزة الأدوار الأخرى، وأرسل الرمز بقناة منفصلة.
4. استورد الملف والرمز من زر «الأمان» في كل دور.
5. خزّن ملف الربط في مكان آمن؛ فقدانه مع مسح تطبيق الإدارة يعني تعذر استعادة مفتاح المزامنة.

## المستخدمون والصلاحيات والتكليفات

من نسخة الإدارة افتح «المستخدمون والصلاحيات»، ثم أنشئ المحصلين والكاشفين وحدد صلاحيات كل موظف. لكل موظف اسم مستخدم ورمز إنجليزي فريد من حرفين؛ سند المحصل يأخذ الصيغة `XX-YYYYMMDD-0001` ويزداد تسلسله داخل يوم العمل. لا تحفظ هذه الشاشة كلمة مرور أو رمز دخول داخل JavaScript؛ يبقى قفل التطبيق في الطبقة الأصلية وAndroid Keystore.

بعد ذلك وزّع المشتركين من «إدارة المحصل» أو «إدارة الكاشف». كل ملف تكليف مشفر يحمل هوية الموظف ورمزه وقائمة المشتركين المسموحين. لا تعتمد الإدارة ملف قراءات أو تحصيلات ما لم يطابق تكليفًا تم حفظه فعليًا من جهاز الإدارة.

## تسجيل الدخول باسم المستخدم وPIN

- عند تثبيت التطبيق لأول مرة، يدخل الموظف اسم المستخدم المسجل له في الإدارة وينشئ رمز PIN من 6 إلى 12 رقمًا غير متسلسل.
- اسم المستخدم ليس سرًا، أما PIN فلا يصل إلى JavaScript؛ يحفظ التطبيق مدققًا مشفرًا بمفتاح Android Keystore.
- التكليف المشفر للمحصل أو الكاشف لا يفتح إلا عندما يطابق اسم مستخدم جلسة الدخول.
- عند ترقية نسخة كانت تستخدم PIN فقط، تظهر شاشة ترقية لمرة واحدة تطلب اسم المستخدم والـPIN الحالي، ولا تمسح SQLite أو الحركات السابقة.
- الإعداد التشغيلي المعتمد حاليًا هو مستخدم واحد لكل تثبيت/جهاز. عند تسليم الجهاز لموظف آخر يجب إنهاء وتسليم جميع الحركات أولًا ثم إعادة تهيئة التطبيق بإشراف الإدارة.

## الدخول بالبصمة

- بعد نجاح أول دخول باسم المستخدم وPIN، يعرض التطبيق تفعيل البصمة إذا كان الجهاز يدعم بصمة قوية ومسجلة.
- يمكن تفعيلها أو إيقافها من «الأمان ← إعدادات الدخول والبصمة». إيقافها يتطلب PIN الحالي.
- إلغاء نافذة البصمة أو تعطل المستشعر يعيد المستخدم إلى اسم المستخدم وPIN دون احتساب محاولة PIN فاشلة.
- البصمة تفتح جلسة المستخدم المسجل على الجهاز فقط؛ لا تغيّر صلاحياته ولا تسمح بفتح تكليف موظف آخر.
- عند عدم وجود بصمة مسجلة، يستطيع المستخدم فتح إعدادات Android من شاشة الحماية ثم العودة للتفعيل.

## البناء

### البناء السحابي دون تثبيت أدوات Android

تتضمن الحزمة GitHub Actions جاهزة لبناء ملفات APK الأربعة من المتصفح:

- `Qatra Pro - Build Debug APKs` للاختبار.
- `Qatra Pro - Build Signed Release` للإصدار النهائي بعد إضافة أسرار مفتاح التوقيع الجديد.

اتبع الخطوات العربية في `build-tools/BUILD_APK_WITH_GITHUB_AR.md`.

### البناء المحلي الاختياري

المتطلبات: JDK 17، Android SDK 35، وGradle 8.7 أو Gradle Wrapper.

```bash
cd qatra-pro-secure-v2
gradle wrapper --gradle-version 8.7
./gradlew assembleAdminDebug assembleReaderDebug assembleCollectorDebug assembleCashierDebug
```

للإصدار النهائي، أنشئ مفتاحًا جديدًا خارج المشروع ثم مرر بياناته كمتغيرات بيئة. لا تُكتب كلمات المرور في Gradle أو JavaScript.

```bash
export QATRA_KEYSTORE_PATH=/secure/path/qatra-pro-release.jks
export QATRA_KEYSTORE_PASSWORD='...'
export QATRA_KEY_ALIAS='qatra-pro-release'
export QATRA_KEY_PASSWORD='...'
./build-tools/build-secure-release.sh
```

نواتج البناء تحمل أسماء مثل `qatra-pro-admin-2.7.0-production-candidate.apk`.

إعداد OAuth واختبارات النسخ التلقائي على Google Drive موضحة في
[`GOOGLE_DRIVE_BACKUP_SETUP_AR.md`](GOOGLE_DRIVE_BACKUP_SETUP_AR.md).
